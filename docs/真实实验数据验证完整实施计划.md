> 计划版本：v3.0
> 修订日期：2026-08-28
> 实施者：Codex
> 最终操作者：材料科研人员
> 核心定位：以 UI 人工调参拟合为主，软件负责数据、几何、预览、状态和证据管理

## 0. 优化后的 Codex 执行指令

Codex 应基于当前 audit-fixes 分支继续完善 LamellarSAXS2D，使用户能够在 Qt UI 中载入真实二维 SAXS 图像、PONI 和 mask，人工编辑参数、范围、固定状态和表达式，通过 Observed、Model、Residual、Overlay 四视图反复 Preview，必要时对当前单帧执行一次由用户主动触发的 Optimize，最后保存参数、项目状态、诊断图和来源信息。

本项目当前不建设：

- 无人值守的 120 帧自动全拟合；
- 自动选择“最佳物理解”；
- 全局、多起点或跨帧联合优化体系；
- 物理正演或三维结构反演；
- 面向公开发布的安装包和版本发布流程；
- 自动材料机理判断。

Codex 负责执行代码修改、测试、文档更新和真实数据只读验证。用户不需要照着计划运行命令；只有涉及实验语义、人工调参取舍和最终视觉验收时，Codex 才请求用户判断。

## 1. 项目最终目标

### 1.1 一句话目标

把 LamellarSAXS2D 完善为一套可靠的二维 SAXS 人机协同拟合工具：**软件保证数据和模型显示正确，人通过 UI 调参数完成拟合判断。**

### 1.2 最终工作流

    载入 EDF/HDF5/NPY 等图像
      → 载入 PONI 与外部 mask
        → 显示输入、q 单位、有效像素和校正状态
          → 用户设置 q-window、ROI 和参数
            → Preview 当前参数对应的 Model
              → 比较 Observed / Model / Residual / Overlay
                → 用户继续人工调参
                  → 可选：用户主动点击 Optimize 微调当前单帧
                    → 用户决定是否接受
                      → 保存项目、参数、诊断图和备注

### 1.3 人与软件的职责

| 对象 | 负责内容 |
|---|---|
| Codex | 修改代码、修复接口、完善 UI、建立测试、运行验证、更新文档和 CHANGELOG |
| 软件 | 读取数据、生成 q-map、组合 mask、渲染模型和残差、保存状态、给出辅助指标 |
| 用户 | 选择分析范围、人工调参数、判断图样是否拟合合理、决定是否接受当前结果 |
| 外部实验依据 | 支持材料结构或机制解释；不能由单张二维 SAXS 图自动替代 |

### 1.4 Optimize 的边界

Optimize 可以保留，但必须满足：

- 只处理用户当前打开的单帧；
- 从用户当前参数开始，而不是自动猜测并替代用户选择；
- 严格遵守用户设置的 Min、Max、Vary、Expr、q-window、mask 和 ROI；
- 只有用户点击后才运行；
- 优化前参数、优化后参数都能查看和恢复；
- Optimize 完成不等于结果被用户接受；
- 不自动传播到后续 120 帧。

## 2. 旧计划的迁移原则

旧版以自动拟合为主线的后续阶段编号全部退出当前执行路线，不再作为实施阶段、验收门或后续待办。现有 batch 和自动分析能力只要求保持不回归，不继续扩建。

已经实现的输入检查、自动分析代码、测试和本地证据不删除。它们可以继续提供 ridge 建议、双椭圆初值和失败提示，但不再决定用户能否在 UI 中人工拟合，也不替代用户的最终判断。

### 3.1 已完成基础

当前 audit-fixes 分支已经包含：

- ridge 连续轨迹、lobe、双椭圆和质量状态代码；
- EDF、HDF5、NPY/NPZ、TIFF、CSV/TXT 等输入；
- PONI q-map、外部 mask、ROI 和 q-window；

上一个已推送 P4 合同节点为 eec799e。最近一次记录的全量测试为 249 passed；本轮按“先跑通重要软件主链、跳过不必要测试”的要求，继续以 P4/UI 定向测试和真实数据只读冒烟建立增量基线，全量测试留到最终 UI 收口再运行。

### 3.2 当前真实数据

本地 R0 数据包为 2#_no50s_375_2_iso：

- 1 帧室温参考；
- 120 帧 375 ℃保温序列；
- 包内 PONI；
- 最终 NPY mask；
- 项目上下文和 manifest；
- 原始数据只读，禁止上传。

此前已经用固定 8 帧运行过自动 ridge/双椭圆工程审计，但这不是本项目最终验收。最终验收必须由用户在 UI 中实际调参完成。

### 3.3 当前主要缺口

当前重点不再是继续增强自动算法，而是检查并补齐：

1. 参数表是否与实际经验模型参数一一对应；
2. 人工修改参数后 Preview 是否立即、正确、稳定更新；
3. 四视图的坐标、mask、色阶和模型是否完全重合；
4. 用户是否能看懂每个参数的含义和单位；
5. Optimize 是否严格使用用户当前设置；
6. 优化前后是否可比较、撤回和恢复；
7. 保存项目后能否完整恢复参数、ROI、PONI、mask 和视图状态；
8. 是否能导出一套适合科研复核的人工拟合证据。

## 4. UI 人工拟合合同

### 4.1 输入区

UI 必须明确显示：

- 当前图像路径、格式、frame 和 dataset；
- 图像 shape 与强度单位；
- PONI 路径及 q 单位；
- mask 路径、极性和排除比例；
- q-window；
- ROI；
- 输入校正状态和不确定度状态；
- 红/黄/绿输入提示。

输入存在 shape、selector、PONI 或 mask 冲突时，必须在 Preview 前失败，不能显示一张看似合理但坐标错误的图。

### 4.2 参数表

参数表至少保留当前经验模型使用的参数：

- a；
- axis_ratio，以及由表达式得到的 b；
- radial_sigma、radial_gamma、eta；
- amplitude_plus、amplitude_minus；
- background、background_slope、background_curvature；
- background_amplitude、background_width；
- theta_deg；
- lobe_angle_deg；
- angular_width_deg。

每行必须显示：

- Value；
- Min；
- Max；
- Vary；
- Expr；
- Unit；
- Stderr 或明确的 unavailable。

人工编辑要求：

- 非法数字、越界值和无效表达式立即提示；
- 参数改变不得自动开始 Optimize；
- Auto preview 开启时只运行 Preview；
- Vary=False 的参数不能被 Optimize 改动；
- Expr 参数不允许出现循环依赖；
- degree 与 radian 的内部转换必须唯一；
- b=a×axis_ratio 的关系不能在 UI、模型和导出之间漂移。

### 4.3 Preview

Preview 是当前项目的核心操作，必须：

- 使用用户当前参数；
- 使用当前 q-window、mask、ROI 和权重；
- 生成与 Observed 同 shape 的 Model；
- Residual 明确为 Observed - Model；
- Overlay 显示当前模型轨迹和已有 ridge/lobe 辅助点；
- Observed 与 Model 共用强度色阶；
- Residual 使用以 0 为中心的对称色阶；
- 参数频繁改变时，旧 Preview 不得覆盖新状态；
- 不修改原始图像、PONI 或 mask。

### 4.4 可选单帧 Optimize

Codex 只需保证当前 Optimize 是可靠的人工辅助工具：

- 输入为用户当前参数；
- 输出为当前单帧的一组候选微调结果；
- 用户可以选择接受或恢复优化前状态；
- 显示 RMSE、ndata、coverage、condition 和边界提示；
- 这些指标只供用户参考，不自动宣告科学 PASS；
- Cancel 或 Ignore late result 后，迟到结果不得污染当前项目；
- 不增加自动多起点、自动遍历帧或全序列传播。

### 4.5 拟合历史

每个 UI 会话至少保存：

- 初始参数；
- 每次用户确认保存的参数快照；
- Optimize 前参数；
- Optimize 后参数；
- 用户最终接受的参数；
- 时间、备注和当前帧；
- q-window、ROI、mask 和 PONI。

最低实现可以是清晰的 Save snapshot、Restore snapshot 和 Fit notes，不要求建设复杂数据库。

### 4.6 四视图

四视图必须符合 README 参考图：

| 视图 | 用途 |
|---|---|
| Observed | 显示真实输入和 mask |
| Model | 显示当前人工参数生成的经验模型 |
| Residual | 帮助用户发现峰位、宽度、强度和背景不匹配 |
| Overlay | 将模型轨迹、ridge/lobe 与实验图叠加比较 |

Overlay 中出现两条正负 theta 对称椭圆属于当前镜像约束模型的设计，不得误写成两套独立结构。

## 5. Codex 实施路线

以下阶段全部由 Codex 执行。用户不需要运行命令。

### A：冻结新范围并建立当前基线

**Codex 动作**

1. 以本 v3.0 计划替换旧自动化路线；
2. 检查 audit-fixes 当前工作树和最近提交；
3. 使用现有 .venv-project 运行依赖检查、UI 定向测试和全量测试；
4. 保存基线测试结果；
5. 不删除既有输入检查和自动分析代码。

**验收**

- 当前代码可导入；
- UI 能离屏创建；
- 全量测试零失败；
- 现有用户改动和真实数据保持不变。

**停止条件**

- 环境失效需要联网安装；
- 发现未提交且来源不明的重叠修改；
- 测试失败说明当前基线不可信。

### B：核对输入、模型与参数数据流

**Codex 动作**

1. 追踪 ParameterTableModel → MainWindow → Service → intensity model 的完整数据流；
2. 建立 UI 参数名、核心参数名、单位和表达式的唯一映射表；
3. 检查当前参数表是否实际控制当前单帧经验像素模型的 Preview；
4. 检查 PONI、mask、q-window、ROI 是否传入同一 Preview；
5. 修复任何参数丢失、重复转换或默认值覆盖；
6. 增加非方形图像、不同 q 单位和外部 mask 回归测试。

**主要文件**

- src/butterfly_saxs/ui/models.py
- src/butterfly_saxs/ui/main_window.py
- src/butterfly_saxs/service.py
- src/butterfly_saxs/pipeline.py
- src/butterfly_saxs/intensity.py
- tests/test_ui_workflow.py
- tests/test_service.py

**验收**

- 修改任一 UI 参数，只改变模型中对应部分；
- Preview 参数与导出参数逐项一致；
- degree/radian、a/b/axis_ratio 和 Expr 往返一致；
- 输入冲突在 Preview 前明确失败。

### C：完善人工 Preview 主循环

**Codex 动作**

1. 确保参数编辑后状态变为“有未预览修改”；
2. Preview 完成后标记对应参数版本；
3. Auto preview 做防抖，避免每次键盘输入启动多个任务；
4. 旧 worker 结果按参数版本拒绝；
5. 四视图使用相同坐标、mask 和 extent；
6. 增加参数变化前后 Model/Residual 的确定性测试；
7. 对真实 EDF 做只读 Preview，检查图像和模型空间重合。

**验收**

- 用户连续修改参数时 UI 不冻结；
- 最终显示只对应最新参数；
- Model、Residual、Overlay shape 和坐标正确；
- Preview 不调用优化器；
- 参数改变的视觉效果符合模型含义。

### D：完善单帧 Optimize、快照与恢复

**Codex 动作**

1. Optimize 明确读取用户当前参数、Vary、Min/Max、Expr；
2. Optimize 前自动建立快照；
3. 提供接受、恢复优化前参数的明确动作；
4. 保存人工快照和备注；
5. Cancel/Ignore late result 后阻止迟到结果覆盖；
6. 不添加 multistart、批量传播或全局拟合。

**验收**

- fixed 参数保持不变；
- bounds 和 Expr 生效；
- Restore 能精确恢复优化前参数；
- 保存的人工参数与屏幕一致；
- Optimize 不改变其他帧。

### E：完善项目保存与人工拟合证据

**Codex 动作**

1. 扩展现有项目配置的保存内容：
   - 图像、frame、dataset；
   - PONI、mask；
   - q-window、ROI；
   - 参数表；
   - 快照、最终接受状态和备注；
2. 重新打开项目时恢复同一状态；
3. 导出：
   - observed.png；
   - model.png；
   - residual.png；
   - overlay.png；
   - parameters.csv；
   - fit_session.json；
   - provenance.json；
4. 默认不覆盖已有结果。

**人工接受字段**

fit_session.json 中使用：

- manual_status：unreviewed、accepted、rejected；
- reviewed_by；
- reviewed_at；
- review_notes。

软件不得自动写 accepted。

**验收**

- 保存—关闭—重新打开后输入、参数和会话状态一致；重新 Preview 可重建四视图，项目 JSON 不嵌入探测器尺寸数组；
- 导出参数与 UI 完全一致；
- 原始数据 hash 不变；
- evidence 中明确 empirical_model_only 和 human_review_required。

### F：真实数据 UI 验收与文档收口

**范围**

不自动拟合 120 帧。Codex 从现有 8 帧 R0 包中选择：

- 1 个图样清楚、适合人工拟合的帧；
- 1 个较弱或局部弧段帧；
- 1 个应当难以可靠拟合的负例；
- 必要时再增加 1 个中间状态帧。

**Codex 动作**

1. 启动 UI 并载入第一代表帧、PONI 和 mask；
2. 确认初始界面和四视图正确；
3. 将操作交给用户人工调参；
4. 用户确认参数后，Codex保存快照和证据；
5. 对弱帧和负例重复；
6. 更新 README 与 user_guide_zh，使其以人工 UI 工作流为主；
7. 运行 UI 定向测试和全量测试；
8. 更新 CHANGELOG。

**验收**

- 用户能独立完成人工调参；
- Preview 足以帮助判断峰位、宽度、角度、强度和背景；
- 负例允许用户判断“不适合当前模型”，不强迫输出成功结果；
- 保存结果可重新打开和复核；
- 不需要运行自动全序列拟合。

## 10. 最终目标复述

该项目当前不是自动反演程序，也不需要证明能够无人值守拟合全部 120 帧。

它应成为一个可靠的科研 UI：

- 人决定怎样拟合；
- 软件忠实执行当前参数；
- 四视图帮助人判断好坏；
- Optimize 只是当前单帧的可选助手；
- 参数、数据来源和判断过程可以保存、恢复和复核；
- 任何结果都不越过经验二维模型的科学边界。
